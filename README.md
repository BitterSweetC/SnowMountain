# SNOWLINE · 雪线山间绘本

以本目录原始 MP4 和下方绘本版需求制作的独立项目。新的 Hero 参考为 **01:06–01:27**，世界、色板、画笔路径、页面与 **52 秒 FPV 航线**在本项目重新制作。

2026-09-27 美术修订：重做岩脊起伏、雪岩边界、绘制岩石材质与法线、侧光和山体投影。旧版模型、源文件及画面保留在 `revisions/v1/`；最新性能与局限见验收报告。

## 打开项目

```bash
cd snow-mountain-web
npm ci
npm run dev
```

开发地址默认为 **http://127.0.0.1:5183/**。拖拽环绕、滚轮缩放；Play FPV Flight 播放完整航线，支持暂停、重播和 Return to Free View。空格播放／暂停，Esc 返回。右侧可折叠航线图，顶部可打开旅途手记。

```bash
npm run build
npm run preview
```

生产预览默认 **http://127.0.0.1:4183/**。若端口已占用，以终端实际输出为准。`dist/` 是完整静态网页包，运行所需模型、天空和 Meshopt 解码代码均本地交付，不依赖 CDN。

## 文件与修改入口

- [视频分析](docs/video-analysis.md)、[世界与美术布局](docs/world-layout.md)、[最终验收](docs/validation-report.md)。
- `blender/snow_mountain_world.blend`：可编辑地形、参考图、WORK 高精度修改器源、FPV_Path 与相机动画。
- `exports/snow_mountain_world_baseline.glb`：未压缩基线；`exports/snow_mountain_world.glb`：经验证的压缩版。
- `textures/paint-layout.json`：设计雪带与裸岩窗的路径、宽度和强度；各地块保留颜色贴图与雪岩 mask。

- `scripts/build_world.py`：主脊与分支控制点、地形形状、表面笔触、色板和 52 秒航线。
- 网页分为 `scene.js`、`camera-controller.js`、`main.js` 和 `style.css`，便于分别调整视觉和交互。

## 从源码复现资产

安装网页依赖后，在项目根目录执行（需要 Blender，NumPy 已随 Blender 提供）：

```bash
blender -b --python scripts/build_world.py
node scripts/optimize.mjs
blender -b --python scripts/render_source.py
```

小样：`blender -b --python scripts/build_world.py -- --blockout`。直接编辑 `.blend` 后，可运行 `blender -b --python scripts/export_scene.py` 导出，再运行优化脚本。优化会验证输出，只有零错误才复制至网页。

启动生产预览后执行 `cd snow-mountain-web && URL=http://127.0.0.1:4183 npm run verify`，重新记录完整航线、间距、交互与窄屏结果。需要可启动本机浏览器的环境。

当前采用标准手绘外观材质；没有全屏油画滤镜、全场黑描边或机械二阶阴影。雪岩与笔触为设计路径加程序辅助烘焙，非声称逐像素人工绘画。近景仍有程序化简化，具体差异与未测试设备见验收报告。

## 1. 项目目标

制作一个受到参考视频启发的原创阿尔卑斯雪山世界，从视频提取可信地形、空间尺度和 FPV 飞行体验，再以风格化的色彩、笔触和明暗块面重新演绎，不要求严格复原真实山脉的地理坐标。

核心目标：

- **完整空间**：核心山峰、周边山谷与远景山脉连续衔接，允许从多个角度观察。
- **真实地形**：以有三维体积的 Mesh 构建山峰、山脊与岩壁，近距离飞行时具有可信视差。
- **漫画绘本雪景**：冷暖归纳的雪面与岩壁、蓝紫阴影、手绘笔触、清晰山脊和有方向的戏剧性阳光。
- **FPV 体验**：提供平滑的接近、沿脊、掠峰、入谷与远山揭示镜头。
- **实时交互**：在普通现代电脑浏览器中运行，支持自由观察、缩放与 FPV 播放。
- **可编辑、可复现**：保留 Blender 源文件、烘焙资源、导出设置和网页源码。

### 1.1 统一视觉方向

**Stylized Graphic-Novel 3D / Painterly Stylized 3D — 漫画绘本质感的风格化 3D。**

保留可信的山体比例、巨大空间尺度与真实三维视差，将表面归纳为有设计的大块岩壁、雪面、笔触和冷暖色阶。重点是欧洲漫画与绘本式的图形语言，以及粗粝的高山户外感。

- **几何**：强调峰顶、山脊、断崖和负空间的 silhouette；适度简化碎石，避免均匀三角切面与夸张卡通比例。
- **材质**：手绘色块与沿地形走向的笔刷纹理为主，保留适量粗糙感；不追求扫描级细节或照片级 PBR 外观。
- **明暗**：大面积亮面、中间调、冷色暗面支撑体积；边界可明确但保留适度过渡，避免传统 anime cel-shading 的机械二阶阴影和全场粗黑描边。
- **氛围**：天空、云和雾像概念艺术背景；远景降低纹理频率、饱和度与对比，保持山脉层次。
- **验收**：缩小画面或去色后，主峰、雪岩分区和三层空间仍然清楚；近看有笔触，运动时稳定。

明确避免纯照片级写实（photorealistic）、写实扫描纹理堆叠、传统日漫赛璐璐风，以及靠全屏滤镜把普通写实资产伪装成绘本。标准 PBR 通道仍可作为 Web 材质载体；使用它不代表以照片级写实为美术目标。

### 1.2 色彩与材质设计基准

以下是起始设计色板，不是从视频采样得到的事实；最终在浏览器统一曝光与色调映射后调整。

| 角色 | 起始 sRGB 色值 | 使用方式 |
| --- | --- | --- |
| 日照雪面 | `#E8E5D8` | 温暖的浅色大面，保留亮部层次，避免大片纯白 |
| 背光雪面 | `#8C9FBE` | 冷蓝中间调，跟随坡面形态 |
| 深阴影 | `#606B8B` | 蓝紫暗部，避免死黑 |
| 受光岩壁 | `#807A71` | 暖灰块面，与冷雪阴影形成色温差 |
| 背光岩壁 | `#454C5D` | 冷灰主暗面，仍可读出岩壁结构 |
| 远山与雾 | `#A5B6CA` | 逐层向天空色靠拢，不抹掉剪影 |
| 高空底色 | `#718EA9` | 与地平线浅色渐变衔接，可加入稀疏手绘云带 |

固定这些颜色的角色比固定色值更重要。制作时记录到既有的 `docs/world-layout.md`，同时注明主光方向、笔触尺度、雪岩边界示例与浏览器材质方案。

### 1.3 可复用视觉提示词

```text
Stylized cinematic alpine mountain environment with a European graphic-novel
and painterly 3D illustration aesthetic. Maintain believable mountain scale,
terrain proportions, spatial depth, and FPV parallax. Simplify surface details
into strong rock planes, designed ridge silhouettes, hand-painted textures,
visible directional brushwork, controlled color blocks, cool blue-violet snow
shadows, warm/cool gray rocks, and graphic snow/rock separation. Use dramatic
directional lighting, restrained highlights, a painted sky, and layered
atmospheric haze. Keep materials and effects compatible with a Blender to
GLB to Three.js real-time workflow. Avoid photorealism, scan-like microdetail,
traditional anime cel-shading, thick uniform black outlines, exaggerated
cartoon proportions, and indiscriminate low-poly triangulated surfaces.
```

### 2.2 全片分析内容

完整查看视频；可先粗采样建立全片索引，再细看候选区间及其前后衔接。

| 分析维度 | 需要记录的内容 |
| --- | --- |
| 地形 | 主峰、山脊轮廓、山谷、雪坡、裸露岩壁、沟槽与峰高变化 |
| 空间 | 遮挡关系、前中后景层次、远山分布、可扩展的周边地形 |
| 材质 | 观察积雪分布、雪岩交界与坡面差异；提取可归纳的大色块和笔触走向，不直接复制摄影纹理 |

## 3. 完整工作流

```text
完整参考视频
    ↓
全片分析 → 3～5 个候选片段 → 选定 Hero Segment
    ↓
世界布局：Hero Area + Midground + Background
    ↓
默认构图与航线草案 → Terrain Blockout → 浏览器小样验证
    ↓
Hero 块面与剪影精修 → 手绘雪岩材质 → 中远景色阶 → 风格化光照与大气
    ↓
FPV Camera Animation
    ↓
Web 优化与纹理烘焙
    ↓
未压缩基线 GLB → 验证 → 按瓶颈优化 → 最终 GLB
    ↓
Three.js 交互网页
    ↓
视觉、动画、交互、性能与生产构建验收
```

`.blend` 是可编辑的制作源文件，`.glb` 是浏览器运行资产。每个阶段都要检查是否满足下一阶段需求；轮廓、空间或相机出现明显问题时，先修正，再增加细节。

如果执行环境提供 `blender-reference-web` 或等效 Blender-to-Web-3D 技能，优先采用其制作、导出和验证工作流。建模早期就应导出小样，确认基本材质与相机能进入浏览器。

<a id="world-design"></a>
## 4. Hero Area / Midground / Background 设计

| 层级 | 职责 | 主要内容 | 精度与验收重点 |
| --- | --- | --- | --- |
| **Hero Area** | 承担贴近飞行与视觉焦点 | 主峰、核心山脊、山谷、岩壁、雪槽、积雪边缘 | 最高相对精度；轮廓、岩壁主块面、近景笔触和雪岩交界清晰，整条航线不穿模 |
| **Midground** | 延续地形并产生中景视差 | 次峰、连接山脊、谷地、坡面与周边岩体 | 中等精度；减少碎纹理，保留大色块与结构走向；衔接自然，多角度观察无断层、空洞或悬空山体 |
| **Background** | 建立规模与地平线 | 低复杂度山脉、峰群剪影、远景色阶与薄雾 | 较低精度；以少量色阶和峰群剪影读形，弱化笔触，与绘画式天空及中景自然融合 |

设计要求：

- 先确定主峰、山脊走向、谷地开口与航线，再安排辅助山峰。
- 通过相连地形、遮挡、远山与大气共同处理边界，避免突然截断。
- 在规划的全部自由观察范围和 FPV 航线上验证世界完整性，覆盖两侧和可能看到的背面。
- 不以一张雪山图片代替可接近、可环绕的山体；天空背景和云层可采用适合 Web 的独立方案。
- 自由观察的距离、俯仰与移动范围应足以查看整体世界，同时避免进入未设计区域。需要完全无约束探索时，应相应扩大地形覆盖。

这里的三层是**空间设计层级**。同一物体的 LOD0 / LOD1 / LOD2 是另一套按距离切换的几何方案，按性能需要另行设计。

## 5. Blender 场景与建模规范

### 5.1 场景组织

建议使用以下制作结构：

```text
SnowMountainWorld
├── REFERENCE                         # 视频帧、构图参考，不导出
├── WORK                              # 高模、雕刻源、烘焙笼，不导出
├── WEB_EXPORT                        # 明确的运行资产导出范围
│   ├── Terrain
│   │   ├── Hero_Mountain
│   │   ├── Hero_Ridge
│   │   ├── Hero_Valley
│   │   ├── Midground_Mountains
│   │   └── Background_Mountains
│   ├── Snow
│   │   ├── Snow_Main
│   │   └── Snow_Detail
│   ├── Rocks
│   │   ├── Rock_Formations
│   │   └── Cliff_Details
│   ├── Atmosphere
│   │   └── Clouds_Web                # 若使用网格或云片
│   └── Cameras
│       ├── Web_Default_Camera
│       └── FPV_Camera
├── LIGHTING                          # Sun、Environment 等制作参考
├── ATMOSPHERE_PREVIEW                 # 天空、雾与体积效果预览
└── FPV_Path                          # 可编辑航线，烘焙后不必导出曲线
```

上述结构可以用 Collection 管理，但网页依赖的父子关系应以实际对象或 Empty 层级表达，并检查导出结果。对象及动画使用唯一、稳定的 ASCII 名称；优化时保留网页引用的节点。

### 5.2 地形制作顺序

1. 建立主峰、山脊和谷地的低复杂度 Blockout，确定默认相机与飞行走廊。
2. 检查大尺度起伏、剪影、峰高变化和前后遮挡。
3. 使用程序化位移、Noise 类地形逻辑、Geometry Nodes、Sculpt 或 Multiresolution 丰富体积。
4. 手工修正 Hero Area 的陡峭岩壁、雪槽、侵蚀形态与重要山脊，将细碎侵蚀归纳为较大的结构面。先检验剪影，再调整块面法线；不可把每个三角面都做成同等醒目的折面。
5. 准备适合网页的网格、UV、法线和烘焙贴图，再添加影响近景的次级细节。

程序化工具用于生成基础，不应让最终地形表现为均匀、无主次的随机噪声。工具和节点名称以安装的 Blender 版本为准。

### 5.3 几何与资产规范

- 使用一致尺度，默认按米组织；记录原点、地面基准和主要朝向。
- 相机可见区域不得出现破面、错误法线、明显裂缝或意外重叠。
- 网页网格保留影响山脊剪影和近景视差的几何，微小纹理优先归纳或省略，需要的笔触使用贴图；不可用强法线噪声替代形体设计。
- 检查 UV 接缝、密度与烘焙留边；需要唯一烘焙的区域避免意外 UV 重叠。
- 在源文件中保留可编辑修改器与高模；导出副本使用经过验证的求值结果。
- Geometry Nodes、实例与位移应根据导出路径转换或实现，核实结果是否完整。
- 按对象需要处理 Scale / Rotation；避免对相机动画或依赖父级变换的对象批量应用变换而改变运动。

<a id="materials"></a>
## 6. 雪与岩石材质

### 6.1 风格化 snow / rock breakup

以浅色雪面与较暗岩壁构成清晰的图形关系。先根据坡度、朝向、海拔、曲率、沟槽与低频噪声生成积雪候选遮罩，再人工绘制和修正，避免程序化噪声决定全部边界。

- 陡崖以裸岩为主，缓坡、凹陷与沟槽聚雪；这些规律服务于可信地形。
- 海拔只作辅助，不允许整齐水平雪线；朝向与风积雪的推断单独记录。
- 将零碎雪点合并成有节奏的大雪带、雪槽和留白，保留主峰最有辨识度的交界形状。
- 边界总体清晰，局部加入稀疏手绘缺口与软过渡；避免全域碎噪声、均匀锯齿或照片级颗粒。
- 镜头掠过的雪檐、岩脊和堆积体积使用 Mesh；表面笔触使用贴图，避免透明叠层模拟所有积雪。
- 岩壁明暗跟随结构面和裂隙走向，雪面笔触跟随坡面与积雪流向；不要将相同随机纹理均匀覆盖全山。

### 6.2 手绘纹理与色块

按“大色块 → 次级结构 → 少量笔触”的顺序绘制。雪使用偏暖亮面与蓝紫冷暗面，岩石使用有冷暖变化的灰色，不以纯白雪和纯黑岩石压扁层次。

Hero Area 的笔触在近景可见，但不盖过岩壁体积。中景减少笔触密度，远景主要保留色块和轮廓。笔触固定在物体表面，默认使用 UV 贴图；避免随屏幕或相机游动。为接缝、mipmap 与压缩保留足够留边，完整 FPV 航线上检查重复图案、纹理拉伸与远处闪烁。

Base Color 中允许画入固有色变化和克制的结构色差。需由实时灯光产生的直射阴影、高光不重复烘入基础色；若某个远景资产选择完整绘制明暗，应采用明确的 unlit 方案，避免再叠加实时照明。

### 6.3 Web 材质载体与烘焙

默认采用**手绘 Base Color + 高粗糙度非金属材质 + 克制的法线 + 浏览器艺术化照明**。首先让标准材质的小样成立，只有确实需要额外明暗控制时才加入第 8 节的自定义 shader。PBR 是兼容载体，视觉目标仍是 painterly stylized 3D。

Blender 的复杂混合节点、笔刷噪声和积雪遮罩保留为制作源；不能直接导出的结果烘焙为运行贴图。不要假定 Shader to RGB、ColorRamp 或任意节点图能作为同样的着色程序装入 GLB。导出选项以实际 Blender 版本核对，参见 [Blender glTF 材质说明](https://docs.blender.org/manual/en/3.2/addons/import_export/scene_gltf2.html#materials)。

| 通道 | 风格化用途 | 交付约定 |
| --- | --- | --- |
| Base Color | 手绘固有色、色块、方向性笔触 | 颜色数据；保持受光与暗部的色相关系，避免重复直射阴影 |
| Normal | 少量岩壁结构与近景表面起伏 | 切线空间、非颜色数据；弱化细碎噪声，不用来替代剪影 |
| Roughness | 宽而克制的反射，避免塑料感与雪面亮点闪烁 | 优先高粗糙度常量，确有差异才加低频数据贴图 |
| Ambient Occlusion | 克制的裂隙与接触层次 | 非颜色数据；避免大面积脏灰和雪面发黑 |
| Metallic | 雪岩非金属 | 默认 0，无需单独贴图 |
| 可选雪岩 mask | 浏览器艺术化分区控制 | 只在自定义材质使用；记录通道、UV 和加载路径，GLB 核心材质不会自动解释 |

离线绘制的 sRGB 色板、颜色贴图与运行时线性光照应遵循统一色彩管理；数据贴图不作颜色转换。保留加载器正确设置的纹理角色，避免二次转换。烘焙后检查近景笔触、远景读形、雪岩接缝与压缩前后色块。

<a id="cameras"></a>
## 7. FPV Camera 与默认视角

### 7.1 Web_Default_Camera

网页首次加载时采用此相机的构图：清晰看到 Hero Mountain，同时保留中景与远景，体现完整世界的尺度。避免起始位置贴近山体或裁切主峰。

自由观察相机可从该构图初始化，并配置对应的 OrbitControls 目标点。宽高比改变时更新投影，检查窄窗口是否仍能辨识主峰。

### 7.2 FPV Flight Corridor

根据 Hero Area 设计有空间意义的路线：

```text
Wide Mountain View       广角建立世界
        ↓
Approach Mountain        接近核心山体
        ↓
Follow Ridge             沿山脊飞行
        ↓
Pass Close to Peak       贴近峰顶掠过
        ↓
Dive / Enter Valley      下探进入山谷
        ↓
Reveal Distant Mountains 转向揭示远景山脉
```

路线应体现前景快速视差、中景相对位移和远景缓慢变化。速度、俯仰、侧倾与转向共同表达 FPV 感，避免强烈随机震动和突兀滚转。

在 Blockout 阶段就检查航线空间；最终逐段检查地形间隙、近裁切、转弯、入谷和终点。保留原始路径曲线，记录航线时长、帧率、起止帧及关键地形节点。

### 7.3 相机动画交付约定

| 类型 | 约定名称 | 作用 |
| --- | --- | --- |
| 默认相机对象 | `Web_Default_Camera` | 初始构图参考 |
| 飞行相机对象 | `FPV_Camera` | 网页飞行时使用的相机 |
| 动画片段 | `FPV_Flight` | 有明确起止时间的完整航线 |
| 制作路径 | `FPV_Path` | Blender 中可编辑的航线来源 |

Follow Path、Track To 或其他约束驱动的运动，应烘焙为相机或其父节点的位置、旋转关键帧；导出时包含相机、必要父节点和动画，并在 GLB 中核实片段名称与长度。Blender 的动画导出模式随版本变化，应记录实际设置。参见 [Blender glTF 动画说明](https://docs.blender.org/manual/id/5.0/addons/import_export/scene_gltf2.html#animations)。

默认采用固定焦距。glTF 2.0 核心动画通道覆盖节点变换与 morph 权重；不要假定镜头焦距、景深或曝光动画会随相机自动导出。确需动态变化时，在网页显式实现并验证所需扩展或逻辑。参见 [glTF 2.0 动画规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#animations)。

网页使用命名片段 `FPV_Flight`，以 `AnimationMixer` 播放，并按秒更新动画。保留导入相机的父子关系，避免脱离动画父节点后丢失运动。参见 [Three.js AnimationMixer](https://threejs.org/docs/pages/AnimationMixer.html)。

<a id="web-compatibility"></a>
## 8. Web 3D 兼容性、光照与大气

最终视觉必须在 **GLB → Three.js** 中成立。Blender 渲染用于制作参考，浏览器效果用于最终验收。制作时在 `docs/world-layout.md` 记录灯光、色板、雾范围与 shader 参数；在既有 `src/scene.js` 管理网页视觉配置。

### 8.1 资产与运行时分工

| 内容 | Blender 制作方式 | Web 交付方式 |
| --- | --- | --- |
| 地形与结构面 | Sculpt、位移、Geometry Nodes、法线设计 | 求值后的 Mesh、法线与贴图 |
| 雪岩色块与笔触 | 手绘纹理、人工修正遮罩、程序化辅助 | GLB 标准材质中的烘焙贴图 |
| 动态明暗归纳 | 材质小样与调色预览 | 可选 Three.js shader；代码和参数随网页交付 |
| 相机路径 | 曲线、约束与关键帧 | 烘焙节点变换动画 |
| 天空 | 概念艺术式渐变、云带与绘制预览 | 天空球/背景贴图或轻量天空 shader |
| 云 | 设计云团轮廓与少量明暗块 | 低复杂度 Mesh 或少量云片 |
| 雾与空气透视 | 分层色阶、体积效果预览 | Three.js fog 或可选高度雾 shader |
| 灯光、曝光与后期 | 制作对照设置 | 网页显式配置；不假定 Blender World 与合成器随 GLB 迁移 |

### 8.2 灯光与阴影

以一个主方向光建立大的受光面和背光面，低强度环境补光维持暗部可读性。参考视频提供方向依据，允许为主峰轮廓和雪岩读形作明确记录的艺术调整。

阴影偏冷蓝紫，受光雪面可微暖；以色温分离和大块明暗加强图形感。阴影边界清楚但保留适度柔和，不做全场二值量化。避免高强度 HDR 环境、镜面亮点、过强 AO、夸张 bloom 或曝光冲白掩盖材质。

先用基础材质与光照核实颜色，再加入可选 shader 和克制调色。轮廓主要由几何、逆光及相邻色块分离；默认不使用全场黑描边，局部细线如确有需要，须检查额外绘制成本和飞行闪烁。

### 8.3 天空、云与绘画式空气透视

天空使用有限冷暖色的渐变与宽阔云带，避免照片 HDRI 直接成为视觉背景。天空背景与环境照明分开配置，不要求绘制天空本身提供物理正确照明。

远山随距离降低饱和度、细节与明暗对比，并渐渐接近天空色；保留相邻山脉间可辨的色阶。基线使用简单雾和远山材质色差；只有谷底层雾明显改善构图时再实现高度雾。自定义天空、云或地形材质必须明确接入雾与色彩输出，避免一部分对象不受雾影响。

云优先使用有体积的低复杂度形体和少量绘制色阶；云片远离贴近飞行走廊。透明方案检查背面、排序、边缘和 overdraw。不得依赖 Blender Volume 或高成本体积光线步进才能成立。

### 8.4 Shader 分级与回退

**默认基线**：标准 GLB 材质承载手绘外观，Three.js 提供灯光、天空与雾。这个版本必须已经呈现目标风格，可独立完成整条 FPV 航线。

**可选增强**：只在必要的雪岩材质上加入宽阔、平滑过渡的明暗色带，将亮面、中间调和暗面分别映射到设计色彩；允许用固定在表面的低频笔触轻微扰动过渡。避免硬阶梯、随机逐帧噪声、屏幕空间游动纹理及复杂多重采样。不要将所有材质无差别替换成单一 toon shader。

实现必须满足：

1. 使用稳定材质名或明确的元数据匹配需要增强的材质，保留原始标准材质作为回退。
2. 自定义代码显式处理所需贴图、法线、阴影、雾和颜色输出；未实现的能力不假定自动继承。
3. shader 代码属于 Three.js 项目，不是 GLB 自动携带的 Blender 材质图。额外 mask、渐变查找表等资源必须有加载路径及缺失回退。
4. 记录实际 Three.js 版本；若修改内建 shader，升级依赖后重新检查编译和画面。
5. 增强关闭、编译失败或设备性能不足时恢复手绘标准材质，保证模型、相机与交互仍能运行。

不把重型后期描边、全屏油画滤镜或复杂自定义 shader 作为交付前提。最终比较默认构图、掠峰、入谷和远景揭示四类镜头的风格与帧时间。

<a id="performance"></a>
## 9. 性能优化

默认面向普通现代电脑浏览器。开发早期记录目标设备、浏览器、窗口分辨率、期望帧率与加载时间，再根据实测制定预算；未测量前不承诺通用面数上限或已达成的 FPS。

| 观察指标 | 优先检查与处理 |
| --- | --- |
| 三角形与顶点数 | 简化中远景、减少无效细分，将无用微细节删去，必要结构烘焙到低强度法线；保护重要剪影与雪檐 |
| Draw calls 与材质数 | 复用材质、合理合并静态对象、减少不必要材质槽 |
| 重复岩石与装饰 | 复用 Mesh；验证实例化在最终导出与加载路径中生效 |
| 贴图与显存 | 按画面占比与笔触尺度选择尺寸，优先复用图集；不默认采用 4K/8K 扫描纹理，检查色块、UV 与色彩角色 |
| GLB 下载体积 | 检查几何、贴图和动画各自占比，再选择压缩方式 |
| 透明与阴影成本 | 减少重叠云片、控制阴影范围与分辨率、限制后期开销 |
| 高像素密度显示 | 设置合理像素比上限，提供必要的画质调整 |
| Shader 成本 | 优先标准手绘材质；减少多层噪声、采样和 shader 变体，增强可关闭 |
| 笔触与色带稳定性 | 检查 mipmap、压缩色偏、mask 边缘、LOD 色块跳变和 FPV 中的闪烁 |
| 后台页面 | 暂停或降低无必要的持续渲染，恢复时避免动画时间跳变 |

风格化不会自动保证更快。把成本优先分配给轮廓、近景体积和清晰笔触，而非摄影微细节；复杂 shader、透明云和全屏后期仍可能成为主要瓶颈。建议基线档保留手绘材质、主光和简单雾，增强档按测量增加阴影质量与可选 shader；降低画质时保留色板和大块面。

优化顺序：

1. 导出并保留未压缩基线，先完成浏览器验证。
2. 测量瓶颈，优先删除无效成本，再进行有损简化。
3. 按需要增加 LOD、几何压缩或纹理压缩，一次调整一类因素。
4. 每次优化后重新检查山脊轮廓、雪岩接缝、相机动画、节点名称和交互。
5. 对比优化前后体积、画质和帧时间，记录最终取舍。

如采用 LOD0 / LOD1 / LOD2，应在 Three.js 中明确实现切换并检查轮廓、雪线、笔触密度与色块跳变；不假定 Blender 的命名会自动生成网页 LOD。合并网格也应兼顾视锥裁剪粒度。

Draco 或 Meshopt 用于相应几何数据压缩，KTX2/Basis 可用于纹理交付。按实际资产配置 `DRACOLoader`、`MeshoptDecoder` 或 `KTX2Loader`，不无条件加入所有解码器。参见 [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)。下载体积变小并不自动意味着 draw calls 或运行时显存降低。

<a id="glb-export"></a>
## 10. GLB 导出与验证

最终运行资产命名：

```text
snow_mountain_world.glb
```

未压缩基线建议另存为 `exports/snow_mountain_world_baseline.glb`，最终版同步到网页的 `public/models/`。

### 10.1 导出前检查

- 保存 `.blend` 源文件，确认导出范围不含参考平面、高模试验和烘焙笼。
- 检查尺度、旋转、原点、法线、UV、手绘贴图引用与标准材质回退。
- 检查雪岩遮罩的烘焙结果、笔触接缝、色块压缩误差，以及自定义 shader 所需的稳定材质名。
- 区分嵌入 GLB 的资产与由网页提供的天空、雾、调色和 shader；如使用 unlit，验证对应扩展与最终显示。
- 检查修改器、位移和实例的实际导出结果，保留源数据。
- 包含 `Web_Default_Camera`、`FPV_Camera` 及其必要父节点。
- 包含 `FPV_Flight`，核实开始、结束、时长与动画采样质量。
- 避免丢失或重命名网页需要的对象、动画和层级。
- 由导出器处理坐标系转换，在浏览器核实朝向，不重复添加补偿旋转。
- 优先将运行必需贴图嵌入 GLB；需要外部文件时明确相对路径与交付清单。
- 记录 Blender 版本、导出选项、扩展与优化过程。

### 10.2 验证顺序

1. 检查文件非空、结构可读取，统计场景、节点、Mesh、材质、贴图、相机和动画。
2. 使用 [Khronos glTF Validator](https://github.khronos.org/glTF-Validator/) 检查；修复错误，记录并解释保留的警告。
3. 在实际 Three.js 网页中加载未压缩基线，核实手绘材质、色板、剪影、比例、相机和完整航线；分别检查 shader 增强与关闭时的结果。
4. 按需要优化，重新执行结构、视觉和动画检查。
5. 将最终版用于生产构建，检查资源路径和解码器文件。

仅生成文件不能视为导出成功；必须在浏览器中完成实际加载与播放。导出报告记录文件大小、三角形/顶点数量、材质/贴图数量、动画片段、所需扩展和验证结果。

### 11.2 运行约定

以下命令适用于网页项目及其依赖文件已经创建完成之后。开发时记录实际使用的 Node.js、Blender 和 Three.js 版本，并提交依赖锁文件。

首次安装依赖并启动开发服务：

```bash
cd snow-mountain-web
npm install
npm run dev
```

之后使用已提交的锁文件复现安装，可执行 `npm ci`。构建及本地预览：

```bash
npm run build
npm run preview
```

`package.json` 应提供与以上命令对应的 `dev`、`build`、`preview` 脚本。打开终端显示的本地 HTTP 地址；不要直接双击 `index.html` 以 `file://` 运行。

### 11.3 网页运行要求

- 加载 GLB 后显式选择默认相机；核实所需相机和 `FPV_Flight` 存在。
- 缺少模型、相机或动画时显示明确提示，避免空白页面或无效按钮。
- 调整窗口时更新渲染尺寸、像素比与当前相机投影。
- 显式设置环境、输出色彩、曝光和阴影，并与风格化目标构图对照。
- 加载后按材质约定应用可选增强；初始化失败时使用标准手绘材质，避免场景变黑。
- 压缩资产使用匹配版本的解码器；KTX2 在初始化时检测渲染器支持。
- 本地交付所需运行资源应完整；生产构建检查模型、环境图、WASM 与 worker 的路径。
- 更换场景或销毁页面实例时清理不用的几何、材质、贴图及其他 GPU 资源。

<a id="interaction"></a>
## 12. 网页交互

页面保持简洁，以雪山场景为主体。必需按钮为 **Play FPV Flight** 与 **Return to Free View**；可按体验增加暂停、重播和重置视角。

| 状态 / 操作 | 预期行为 |
| --- | --- |
| 加载中 | 显示加载状态；无法确定总量时不显示虚假百分比，模型就绪前禁用播放 |
| 默认自由观察 | 使用默认构图，支持拖拽旋转、Orbit 与 Zoom，可查看整个雪山世界 |
| Play FPV Flight | 保存自由相机及 target，暂停其控制更新，切换 FPV 相机，从航线起点播放 |
| FPV 飞行中 | 按烘焙动画更新镜头，OrbitControls 不覆盖相机姿态，始终可退出 |
| 飞行结束 | 保持结束画面并提供返回或重播操作，避免意外重复循环 |
| Return to Free View | 停止 FPV 播放，恢复此前自由相机和 target，再启用交互 |
| 加载失败 | 展示可理解的错误信息与重试入口 |

相机切换应使用可控的过渡，或明确的直接切换；不让过渡路径穿过山体。用户返回自由模式后仍可再次播放完整航线。

窄窗口下按钮与提示不得遮挡主要操作区域。自由观察限制应与已建世界范围相符，完整检查边界、背面和山谷视角。

<a id="phases"></a>
## 13. 分阶段执行流程

按照以下 15 个阶段推进，每阶段记录产物与检查结果。阶段检查是技术验收；不需要为每一步默认增加用户确认。

| Phase | 阶段 | 主要产物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 1 | Full Video Analysis | 全片地形、材质、光照与飞行记录 | 覆盖全片，观察与推断分开记录 |
| 2 | Candidate Segment Selection | 3～5 个带时间的候选与对比 | 每段均评估三维层次、视差、建模成本与 Web 可行性 |
| 3 | Hero Segment Selection | 最终时间范围、Hero Frame 与取舍 | 选定片段可支持核心地形和有意义的飞行 |
| 4 | World Layout Design | 三层布局、默认构图、航线草案、色板与美术配置 | 首轮分析输出完整，外围延伸与观察范围明确 |
| 5 | Terrain Blockout | 基础山峰、山脊、谷地与浏览器小样 | 大尺度轮廓和视差成立，相机及基础导出可用 |
| 6 | Hero Area Sculpt | 主峰、岩壁大块面、雪槽与归纳侵蚀形态 | 核心剪影明确，近距离观察具有可信体积 |
| 7 | Snow / Rock Materials | 人工修正雪岩遮罩、手绘材质与烘焙试样 | 大色块清楚，笔触稳定，标准材质及可选增强路径可行 |
| 8 | Midground + Background | 中景延伸、远山剪影与色阶 | 允许视角中地形连续，细节随距离归纳 |
| 9 | Lighting + Atmosphere | 艺术化主光、绘制天空、云与雾方案 | 浏览器色块与冷暖关系成立，雪面不过曝，避免机械二阶阴影 |
| 10 | FPV Camera Path | 定稿航线与烘焙动画 | 无穿模，转向平滑，关键地形可辨认 |
| 11 | Web Optimization | 网格、材质及资源预算调整 | 根据实测优化，保护剪影、动画与节点约定 |
| 12 | Texture Baking | 最终手绘运行贴图与可选 mask | UV、接缝、笔触、法线、色彩与压缩检查通过 |
| 13 | GLB Export | 基线版、优化版与导出报告 | 结构验证、浏览器加载和动画检查通过 |
| 14 | Three.js Viewer | 可运行网页及交互 | 默认观察、播放、返回、重播与错误状态可用 |
| 15 | Final Testing | 视觉、功能、构建与性能报告 | 交付物齐全，测量结果及已知差异明确 |

阶段不是阻止提前验证的边界：Phase 5 就进行最小导出与加载，Phase 7 测试材质烘焙，Phase 10 测试相机动画；Phase 13、14 汇总完成正式交付。

### 14.2 验收清单

- [ ] 已完成完整视频分析，并由执行者选择 Hero Segment。
- [ ] Hero、中景和远景共同形成连贯世界，允许视角中没有明显断层和模型边界。
- [ ] 雪山为有可信比例的三维地形，整体呈现 graphic-novel / painterly stylized 3D。
- [ ] 雪岩大色块与蓝紫阴影可读，近景有方向性笔触，远景不被微细节淹没。
- [ ] 无照片级扫描外观、传统 anime cel-shading、全场粗黑描边或夸张卡通比例。
- [ ] 天空与雾具有绘画式层次；缩小或去色后仍能读出主峰和三层空间。
- [ ] FPV 运动中笔触不游动，雪岩边界不闪烁，LOD 不造成明显色块跳变。
- [ ] 标准手绘材质回退与启用的 shader 均经浏览器检查，运行代码及额外贴图交付完整。
- [ ] `.blend` 可编辑，高模、路径和重要制作资源保留完整。
- [ ] 最终 GLB 通过结构验证，错误已修复，保留警告有说明。
- [ ] 浏览器中的模型方向、比例、材质、法线与预期构图一致。
- [ ] `FPV_Flight` 可完整播放，无穿模、姿态跳变或控制冲突。
- [ ] 默认观察、旋转、缩放、进入 FPV、退出和再次播放正常。
- [ ] 通过本地 HTTP 加载，关键资源无失败，控制台无未解释错误。
- [ ] 开发服务和生产构建均可运行，所需解码器和纹理路径正确。
- [ ] 窗口缩放与窄窗口布局正常，目标设备上完成性能测量。
- [ ] 验证报告明确列出尚未验证的项目、已知差异和后续编辑入口。
